# 010.4 — Migrate Task Status Display

## Overview

This migration eliminated all usage of the standalone `task_status_to_string` and `plan_status_to_string` helper functions across the codebase, replacing them with idiomatic `.to_string()` calls via the existing `fmt::Display` trait implementations on `TaskStatusValue` and `PlanStatus`.

## What Was Built

The redundant standalone conversion functions were removed and all call sites were migrated to use the `fmt::Display` trait implementations that already existed on the status enums. This produces identical kebab-case string output (e.g., `"waiting-manual-review"`, `"merge-queue"`) with less code and a more idiomatic Rust pattern.

## Technical Implementation

### Files Modified

| File | Changes |
|------|---------|
| `src/api/execution.rs` | Migrated call site (line 52) from `task_status_to_string(v).to_string()` to `v.to_string()`. Updated doc comment to reference `std::fmt::Display` instead of the removed function. |
| `src/persistence/schema.rs` | Deleted the `task_status_to_string` function definition entirely. The `fmt::Display` implementations for `TaskStatusValue` and `PlanStatus` were preserved. |
| `src/persistence/operations.rs` | Migrated 4 call sites in `update_task_status` and `recover_task_status` from `task_status_to_string(&x).to_string()` to `x.to_string()`. |
| `src/overlord/status_machine.rs` | Removed `task_status_to_string` from the import statement. Migrated 4 call sites in `TaskStateMachine::transition` and `PlanStateMachine::transition` to use `.to_string()`. Removed the standalone `plan_status_to_string` function (code review fix). |
| `src/overlord/scheduler.rs` | Removed the explicit `task_status_to_string` import. Migrated 2 call sites in `transition_task_status` to use `.to_string()`. |
| `src/overlord/mod.rs` | Removed the re-export of `task_status_to_string`. |

### Key Changes

- **Removed functions**: `task_status_to_string` (from `schema.rs`) and `plan_status_to_string` (from `status_machine.rs`).
- **Preserved**: The `fmt::Display` trait implementations for `TaskStatusValue` and `PlanStatus` in `schema.rs` — these are the replacement mechanism.
- **Migrated call sites**: 10 total across 4 files, all now using `.to_string()` via the `Display` trait.

### Additional Code Review Fixes

Beyond the original plan scope, the following fixes were applied during code review:

1. **`plan_status_to_string` migration**: The standalone `plan_status_to_string` function in `status_machine.rs` was also migrated to use `PlanStatus`'s existing `fmt::Display` implementation and then removed, applying the same pattern as the task status migration.
2. **Dead code removal**: Both removed functions had no remaining callers after migration, so they were fully deleted.
3. **Comment fix**: The doc comment in `execution.rs` was updated to reference `std::fmt::Display` instead of the now-deleted `task_status_to_string` function.

## Rationale

- **Eliminates redundancy**: The standalone functions duplicated the exact same logic already present in the `fmt::Display` implementations.
- **Idiomatic Rust**: Using `.to_string()` via the `Display` trait is the standard Rust pattern for type-to-string conversion.
- **Simpler call sites**: `x.to_string()` is more concise than `task_status_to_string(&x).to_string()`.
- **Fewer exports**: Removing the functions reduces the public API surface and re-export chain.

## Usage

No usage changes are required. The `.to_string()` method is available on any type that implements `fmt::Display`, and both `TaskStatusValue` and `PlanStatus` implement this trait. Existing code that previously called `task_status_to_string(&status).to_string()` should now call `status.to_string()` directly.

## Configuration

No configuration changes are required. This is a pure code refactoring with no behavioral changes.
