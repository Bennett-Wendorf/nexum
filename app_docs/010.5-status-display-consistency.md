# 010.5 — Status Display Consistency

## Overview

This spec establishes a codebase-wide convention for string conversion of status enums and typed values: **always use `fmt::Display`**, never standalone `*_to_string` functions. It audits the codebase to confirm no violations remain, documents the convention in source code, and adds an automated check to prevent future regressions.

This work follows up on spec 010.4, which removed a specific instance of the anti-pattern (`plan_status_to_string`). Spec 010.5 generalizes the fix into an enforceable convention.

## What Was Built

Three deliverables were created:

1. **Convention doc comment** — Added to `src/main.rs` crate-level documentation, making the rule visible to any developer reading the crate root source.
2. **Lint configuration note** — Added to `Cargo.toml` under `[lints.clippy]`, referencing the convention and pointing developers to the check script.
3. **Automated check script** — `scripts/check-display-consistency.sh` — a grep-based CI check that detects standalone `*_to_string` function definitions and flags them as violations.

## The Convention

> All status enums and typed values in this crate that require string representation **MUST** use `fmt::Display` for conversion. Do **NOT** create standalone `*_to_string` functions — they duplicate the `Display` implementation and create maintenance burden. Use `value.to_string()` via the `Display` trait instead.

### Why

Standalone `*_to_string` functions (e.g., `fn plan_status_to_string(status: PlanStatus) -> &'static str`) duplicate logic already provided by the `Display` trait. This creates:

- **Duplication**: Two places to update when display logic changes.
- **Inconsistency**: Call sites may use one path or the other, producing different output.
- **Maintenance burden**: New contributors may not know which function to use.

## Audit Findings

A comprehensive scan of all Rust source files (`src/`) confirmed:

- **Zero violations**: No standalone `*_to_string` functions exist in the codebase.
- **Pre-fix state**: 1 `fmt::Display` implementation existed (`ApiErrorResponse` in `src/api/errors.rs`).
- **Post-fix state (after spec 010.4)**: 3 `fmt::Display` implementations exist:
  - `PlanStatus` — in `src/persistence/schema.rs` (added by spec 010.4)
  - `TaskStatusValue` — in `src/persistence/schema.rs` (added by spec 010.4)
  - `ApiErrorResponse` — in `src/api/errors.rs` (pre-existing, legitimate)
- **This spec (010.5)**: Confirms the codebase is clean and establishes prevention via convention doc, lint note, and automated check script.
- All call sites across the codebase use `.to_string()` via the `Display` trait.

### How the Check Script Works

The script (`scripts/check-display-consistency.sh`) performs these steps:

1. **Scans** all files under `src/` for function definitions matching `fn \w*_to_string`.
2. **Filters** out false positives — methods that take `self` or `Self` are excluded, since they are legitimate trait implementations, not standalone functions.
3. **Reports** any remaining matches as violations with file path, line number, and function signature.
4. **Exits** with code `0` (clean) or `1` (violations found).

```
Exit 0 — No standalone *_to_string functions found (clean)
Exit 1 — Violations detected (see output for details)
```

## Usage

### Running the Check

```bash
bash scripts/check-display-consistency.sh
```

On a clean codebase, the output is:

```
Checking for standalone *_to_string functions that duplicate fmt::Display...
✅ PASS: No standalone *_to_string functions found.

Convention: Use fmt::Display for string conversion.
See src/main.rs for details.
```

### Adding a New Status Enum

When adding a new enum that needs string representation:

```rust
/// Correct: implement Display
impl fmt::Display for MyStatus {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            MyStatus::Active => write!(f, "active"),
            MyStatus::Idle   => write!(f, "idle"),
        }
    }
}

// Usage: status.to_string()
```

```rust
/// Anti-pattern: standalone function
fn my_status_to_string(status: &MyStatus) -> &'static str {  // ❌ DO NOT DO THIS
    match status {
        MyStatus::Active => "active",
        MyStatus::Idle   => "idle",
    }
}
```

## Configuration

No configuration is required. The convention is enforced by:

- **Source code**: Doc comment in `src/main.rs` (crate-level documentation).
- **Project metadata**: Note in `Cargo.toml` under `[lints.clippy]` (lines 38–41).
- **Automated check**: `scripts/check-display-consistency.sh` — can be wired into CI pipelines.

## Notes

- The `ApiErrorResponse` `Display` implementation is **not** a violation — it serves a legitimate purpose for error logging and has no corresponding standalone `*_to_string` function.
- `FromStr` implementations (the inverse of `Display`) are **not** part of this anti-pattern — they serve a different purpose (parsing strings into enum values).
- The grep-based script approach was chosen over a custom Clippy lint because the pattern is simple and the script provides contextual error messages. If the pattern reoccurs frequently, consider upgrading to a proper Clippy plugin.
