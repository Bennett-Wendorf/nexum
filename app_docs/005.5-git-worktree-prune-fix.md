# Git Worktree Prune Fix

## Overview

Fixed stale git worktree metadata that accumulated when worktree directories were removed via filesystem fallback (`fs::remove_dir_all`) rather than through `git worktree remove`. After manual directory removal, git's internal worktree database (`.git/worktrees/`) retained entries for deleted worktrees, causing `git worktree list` to show ghost entries and potentially blocking new worktree creation at the same path.

## What Was Built

Added `git worktree prune` calls in the fallback paths of both `remove_worktree` and `remove_worktree_force` in `src/git/worktree.rs`. When git-based removal fails and the code falls back to `fs::remove_dir_all`, the prune command now runs afterward to clean up stale metadata in `.git/worktrees/`.

## Technical Implementation

### Files Modified

- **`src/git/worktree.rs`** — Added prune calls in two fallback paths
- **`src/git/tests.rs`** — Added regression test for prune-after-fallback behavior

### Removal Fallback Chain

Both `remove_worktree` and `remove_worktree_force` follow a cascading fallback strategy:

#### `remove_worktree` (line 118)
1. `git worktree remove <path>` — normal removal
2. `git worktree remove --force <path>` — force removal (for stale/locked worktrees)
3. `fs::remove_dir_all(&path)` — manual directory deletion
4. **`git worktree prune`** — clean up stale metadata (new)

#### `remove_worktree_force` (line 194)
1. `git worktree remove --force <path>` — force removal
2. `fs::remove_dir_all(&path)` — manual directory deletion
3. **`git worktree prune`** — clean up stale metadata (new)

### Key Design Decisions

- **Prune only in fallback paths**: When `git worktree remove` succeeds, git already cleans up `.git/worktrees/` metadata. Prune is only needed when we bypass git and use `fs::remove_dir_all` directly.
- **Non-critical errors**: Prune errors are ignored with `let _ = ...` since the directory is already removed. Prune failure indicates a deeper git issue (corrupted `.git/worktrees/`, permissions) that does not block the caller.
- **Performance**: `git worktree prune` is fast — it only reads `.git/worktrees/` and removes entries whose directories no longer exist.

### Key Code Addition (pattern in both functions)

```rust
// Fall back to manual directory removal
fs::remove_dir_all(&wt_path).await.map_err(|e| GitError::Io {
    path: wt_path.clone(),
    source: e,
})?;
// Prune stale worktree metadata from git's internal database.
// fs::remove_dir_all removes the directory but leaves entries in
// .git/worktrees/, causing `git worktree list` to show stale entries.
let _ = git(repo_root, &["worktree", "prune"]).await;
```

## Regression Test

A regression test was added to `src/git/tests.rs`:

**`test_remove_worktree_fallback_prunes_metadata`** (line 172)

The test verifies the complete fallback-and-prune flow:
1. Creates a test repo and spawns a worktree (`TASK-PRUNE`)
2. Corrupts the worktree by deleting its `.git` pointer file, forcing the fallback path
3. Calls `remove_worktree` and verifies it succeeds
4. Confirms the worktree directory is gone via `worktree_exists`
5. Runs `git worktree list` and asserts the removed worktree no longer appears
